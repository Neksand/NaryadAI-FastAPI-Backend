# НарядAI — сердце системы: API, realtime и искусственный интеллект

**Доказательства:** [EVIDENCE](docs/EVIDENCE.md) · [TEST_REPORT](TEST_REPORT.md) · [IMPLEMENTATION_REPORT](IMPLEMENTATION_REPORT.md)

Проверенный срез от 14.10.2026: [отчёт о тестах](TEST_REPORT.md), [изменения](IMPLEMENTATION_REPORT.md), [запуск](DEPLOYMENT.md), [демо](DEMO_SCRIPT.md), [требования](CASE_REQUIREMENTS_MATRIX.md). Старые отчёты в docs относятся к прежним коммитам; их метрики не подтверждают этот срез.

Backend НарядAI предоставляет API нарядов, сотрудников, фотографий, уведомлений и аналитики. Переходы проходят серверную проверку и сохраняются с автором и временем; AI-приёмка формирует рекомендацию для мастера. Состояние готовности и границы проверки зафиксированы в отчётах выше.

## Что он умеет

**Наряды со строгим характером.** Выдать, принять, начать, приостановить, завершить, закрыть, вернуть на доработку — у каждого перехода свои правила: кто может, из какого статуса, с какими полями. Причина отклонения — только из справочника, завершение — только с описанием работ и шифром, внеплан — только с фото «после». Правила применяются на сервере независимо от отображаемых кнопок.

**ИИ можно запустить на ноутбуке или через API.** Локальные правила проверяют полноту отчётов, материалы, сроки и фотографии. В локальном профиле Estimin3n обрабатывает текст, фото и голосовые заметки прямо на ноутбуке. Серверные адаптеры поддерживают Gemini для текста/фото и Groq для аудио. Hosted-вызовы по умолчанию блокирует AI_EXTERNAL_ENABLED=false; включение требует обезличенных данных и ключей. Эти провайдеры в текущем прогоне не вызывались. ИИ только советует — решение о закрытии наряда принимает человек.

**Обновления и уведомления.** Принял рабочий наряд — доска мастера обновилась сама. За это отвечают WebSocket, transactional outbox и фоновые воркеры: события сохраняются в outbox, пропуски номеров отслеживаются, дедлайны мониторятся, уведомления сохраняются в базе. Это уведомления открытого приложения; доставка на заблокированный телефон требует отдельного push-провайдера и ещё не реализована.

**Аналитика, которая находит боль.** Движок инсайтов сам замечает: оборудование ломается чаще нормы, после ППР идут отказы, ночная смена сыплет одним шифром, исполнитель выбивается из темпа. По каждому инсайту — уверенность, объяснение и кнопка «создать плановый наряд».

**Память ремонтов и объяснимый подбор.** При выдаче мастера подсказки не бывают «чёрным ящиком»: `/api/v1/equipment/{id}/similar-repairs` возвращает похожие закрытые ремонты этого оборудования (тот же шифр — в приоритете) с выполненными работами, материалами и причиной совпадения, а `/api/v1/ai/suggest-assignee` — кандидатов с понятными причинами («свободен сейчас», «высокая загрузка: 4 в очереди»). Это совет, решение остаётся за мастером.

**Порядок в данных.** Справочники (участки, оборудование с QR, бригады, люди, шифры, материалы, нормы, причины), ПИН-авторизация с блокировкой после 5 попыток, роли с привязкой к участкам, мягкие удаления, аудит, идемпотентные мутации (повтор с тем же idempotency key возвращает прежний результат), приватное хранилище фото с подписанными ссылками, экспорт отчётов в PDF/XLSX.

## Технологии

Python, FastAPI, PostgreSQL (транзакции + неизменяемые журналы событий), Redis, S3-совместимое хранилище. База, Redis и эмулятор S3 запускаются через Docker Compose; API можно запускать в Compose или из локального Python-окружения.

## Быстрый старт для разработчика

Если `.env` ещё нет, скопируйте `.env.example` и замените `ACCESS_TOKEN_SECRET` на случайную строку длиной от 32 символов. Для обычного запуска контейнерного API (без Estimin3n) выполните:

```sh
docker compose up --build
```

API: <http://localhost:8080>, Swagger UI: <http://localhost:8080/docs>, readiness: <http://localhost:8080/health/ready>.

Для демо-данных в контейнерной конфигурации:

```sh
docker compose up --build -d
docker compose exec api python -m scripts.seed  # демо-данные, если нужны
```

Команда с полным `docker compose up` запускает API внутри базового образа без PyTorch/Estimin3n. Для локального профиля Estimin3n не запускайте контейнер `api`: используйте следующий способ с API на хосте.

Для локальной разработки активируйте Python-среду, запустите зависимости в Compose и сервер на хосте:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
docker compose up -d postgres redis s3
python -m scripts.migrate
python -m scripts.seed
uvicorn app.main:app --host 127.0.0.1 --port 8080 --no-access-log
```

Compose публикует PostgreSQL и Redis только на `127.0.0.1:15432` и `127.0.0.1:16379`, чтобы не конфликтовать с уже работающими на ноутбуке сервисами на стандартных портах. Эти адреса уже указаны в `.env.example`; API в контейнере продолжает подключаться по внутренним именам `postgres` и `redis`.

## Разработка и проверки

```sh
pip install -r requirements-dev.txt   # тесты, ruff, mypy
pytest -q --cov=app --cov-branch      # полный прогон + покрытие (порог 90%)
ruff check app tests                  # линтер
ruff format --check app tests         # форматирование
mypy app                              # статическая типизация
```

Набор объединяет unit-тесты с fake DB и настоящие интеграционные тесты PostgreSQL/API/S3. Для полного прогона нужны локальные сервисы по DEPLOYMENT.md; Docker необязателен при native-запуске. CI (`.github/workflows/ci.yml`) дополнительно поднимает PostgreSQL, Redis и эмулятор S3 через Compose, применяет миграции, загружает сид и прогоняет те же шаги с покрытием.

## Структура проекта

```text
app/
  main.py        сборка приложения, роутеры, жизненный цикл
  config.py      настройки из окружения
  db.py          пул asyncpg
  deps.py        авторизация, роли, идемпотентность
  routers/       HTTP-эндпоинты по разделам (наряды, каталог, AI, аналитика, отчёты …)
  services/      бизнес-логика: AI-проверка, инсайты, экономика, память ремонтов, фоновые задачи
  ai/            провайдер-агностичный слой ИИ (правила, mock, gateway)
migrations/      SQL-миграции (применяются scripts/migrate.py)
scripts/         миграции, сид, утилиты
tests/           pytest-набор (unit + HTTP)
```

### Экономическая аналитика

`POST /api/v1/analytics/economics/operations` считает показатели по нарядам и возвращает оценку затрат. Передавайте ставки труда/простоя и цены материалов в теле запроса: в базе пока нет денежных ставок. Материалы без указанной цены и завершённые наряды без нормы труда остаются помеченными как неполные; API не подставляет выдуманные значения. Нормативные минуты — оценка, а не зарегистрированное фактическое время.

Пример тела запроса для этого endpoint (материальные цены индексируются по UUID из справочника):

```json
{
  "from": "2026-01-01T00:00:00Z",
  "to": "2026-02-01T00:00:00Z",
  "currency": "KZT",
  "labor_rate_per_hour": 4500,
  "downtime_cost_per_hour": 25000,
  "material_unit_prices": {"<material-uuid>": 1200}
}
```

`POST /api/v1/analytics/economics/feasibility` оценивает проектный сценарий по инвестиции, ежемесячной выгоде и расходам: ROI, простой срок окупаемости, NPV и годовой IRR. Это расчёт введённых предпосылок, без налогов, инфляции и стоимости финансирования.

### Локальный ИИ Estimin3n на ноутбуке

Локальный профиль использует Estimin3n для текстовых рекомендаций и объяснений, проверки релевантности работ, сравнения фото «до/после» и распознавания голосовых заметок. Включите его в `.env`:

```env
AI_MODE=external
AI_TEXT_PROVIDER=estimin3n
AI_VISION_PROVIDER=estimin3n
AI_AUDIO_PROVIDER=estimin3n
ESTIMIN3N_ENABLED=true
ESTIMIN3N_CACHE_DIR=.hf-cache
```

Установите дополнительные зависимости в ту же Python-среду, из которой запускается API, и заранее загрузите веса:

```sh
python -m pip install -r requirements-hf-audio.txt
python -c 'from huggingface_hub import snapshot_download; snapshot_download(repo_id="govnejri/Estimin3n", cache_dir=".hf-cache")'
```

Запускайте локальный API из `.venv` на хосте, а PostgreSQL, Redis и S3 оставьте в Compose: базовый Docker API образ намеренно не содержит PyTorch и веса. Первый вызов загрузит модель в память процесса; файлы останутся в `.hf-cache` и не попадут в git. На ноутбуке Apple Silicon автоматически выбирается MPS. CUDA 4-bit требует совместимый NVIDIA хост и `bitsandbytes`; на Mac этот режим недоступен. CPU-режим требует существенно больше памяти и будет медленным.

Индекс весов содержит 8.39 млрд параметров и около 15.7 GB BF16/FP16 данных; карточка рекомендует 24 GB VRAM. Поэтому ноутбук с 24 GB общей памяти работает на границе: перед первым запросом желательно освободить 18–20 GB RAM и закрыть тяжёлые приложения. На CPU модель загружается в BF16, чтобы не удваивать объём весов; без MPS/CUDA генерация всё равно будет медленной. Опубликованных WER/CER результатов для модели нет.

### Исторический серверный профиль без локальной модели

Для нового production-развёртывания используйте standalone `compose.production.yaml` и `.env.production.example` по [DEPLOYMENT.md](DEPLOYMENT.md). Старый профиль ниже включает тестовый Moto и не является готовым production-хранилищем.

На сервер переносите код и `.env.server`, но не `.hf-cache`. Базовый `Dockerfile` ставит только API-зависимости, поэтому локальная модель там не скачивается и не запускается. Создайте серверный env-файл из шаблона, укажите ключи Gemini и Groq, замените секреты и PIN, затем запускайте:

```sh
cp .env.server.example .env.server
APP_ENV_FILE=.env.server docker compose --env-file .env.server up --build -d
```

Поменяйте пароль БД одинаково в `POSTGRES_PASSWORD`, `DATABASE_URL` и `COMPOSE_DATABASE_URL`; при специальных символах URL-пароль нужно кодировать.

Серверный API разрешает origin упакованного Tauri-клиента (`tauri://localhost`, `http://tauri.localhost` и `https://tauri.localhost`) и адрес фронтенда из `CORS_ORIGINS`. После обновления backend пересоберите и перезапустите API на сервере: уже запущенный удалённый API сам эти изменения не получит.

Внешние модели на сервере выбраны явно: Gemini для текста/фото и Groq Whisper для аудио. Экономические расчёты выполняются обычным Python-кодом по введённым ставкам и ценам; LLM не подменяет арифметику. Без заполненных API ключей проект сохранит локальные правила/эвристики, но внешнее распознавание и мультимодальная проверка будут недоступны.
